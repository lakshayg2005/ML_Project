# Final model: ECERC-Revisited (ECERC + L1 + L2 + L3)

The three limitations are merged into one codebase, [`Limitation-3/ECERC/ext/`](Limitation-3/ECERC/ext/). Every
component is a command-line flag, so a single script trains any combination on either dataset. As in the ECERC paper,
there is one method and one checkpoint set per dataset, because the two datasets have different label sets and input
features.

## 1. What the final model is

| Component | From | IEMOCAP | MELD | Why it is (not) used |
|---|---|---|---|---|
| ECERC backbone | paper | ✓ | ✓ | |
| WavLM-large audio features (replace OpenSMILE IS10) | L1, Divyansh | ✓ | – | needs the raw audio; only the IEMOCAP wavs were extracted |
| VAD auxiliary loss + annotator soft labels | L1, Divyansh | ✗ | – | on top of WavLM: −0.5 wF1 and more pair confusions; temperature scaling already calibrates (Section 3) |
| Release task loss (focal γ = 1 on MELD, γ = 0 + class weights on IEMOCAP) | paper's code | ✓ | ✓ | `MELD/loss.py` defaults to γ = 1 (spotted by Keshav) |
| Zero-shot LLM fusion (Qwen2.5-32B, cached scores) | L2, Keshav | – | ✓ | LLM scores exist only for MELD |
| CACG cause gate (dynamic τ, availability mask) | L3, Lakshay | ✓ | ✓ (utility loss) | |
| Temperature scaling on validation | L3, Lakshay | ✓ | ✓ | |
| Seed ensemble (mean of calibrated members) | L3 | 5 seeds | 3 seeds | |

How a prediction is made (MELD shown; IEMOCAP skips the LLM step):

```
features ─► ECERC + CACG (×3 seeds) ─► mean probabilities ─► log-linear fusion with LLM, w = 0.2 ─► ÷ T ─► softmax
                                                              (w and T chosen on validation)
```

The final model beats the authors' released checkpoints by about 1 wF1 on IEMOCAP and 0.5–0.7 wF1 / 2.5 macro-F1 on

What the ablation shows:

1. **WavLM audio (L1) is the largest IEMOCAP gain:** +2.1 wF1. It also makes training far more stable: the seed
   std drops from 0.97 to 0.32.
2. **The LLM fusion (L2) is the largest MELD gain:** +1.1 wF1 and +3.9 macro-F1 over the retrained baseline, and
   Fear and Disgust F1 rise by about 8–9 points. The MELD variants with fusion all lie within about 0.4 wF1 of each
   other.
3. **L2 and L3 complement each other through temperature scaling.** Fusion raises ECE from 3.6 to 16.8, and L3's
   temperature scaling brings it down to 3.1 (3.0 in the final model). Without it the fused model's confidences cannot
   be trusted.
4. **CACG (L3) reduces Happy↔Excited confusion**, which is Limitation 1's target pair: 84 → 77 on its own and
   88 → 79 on top of WavLM. Angry↔Frustrated does not improve.
5. **The VAD loss and soft labels (L1) are left out of the final model.** They cut *raw* ECE sharply (13 → 5), but
   on top of WavLM they cost about 0.5–0.7 wF1 and add Happy↔Excited confusion. A likely reason, not tested here, is
   that annotators split their votes on exactly these pairs, so the soft targets teach the model to hedge between
   them. Once temperature scaling is applied, the WavLM variants all reach ECE ≈ 2.5–3, with or without these losses,
   so their calibration benefit disappears.
6. **The CACG gate adds no measurable accuracy on MELD.** It changes wF1 by −0.4 alone and +0.2 with fusion, both
   close to the seed noise. The plain ECERC + LLM ensemble (67.31 wF1 / 54.29 mF1) is slightly above the final ensemble.
   CACG stays in the MELD model for the per-utterance cause weights it provides, not for accuracy.
7. **The MELD loss matters for calibration.** The release's focal γ = 1 gives +0.5 wF1 and +0.8 mF1 over γ = 0, and
   raw ECE falls from 9.5 to 3.6.

## 4. Caveats (say these in the report)

- **Choosing the IEMOCAP configuration.** The choice was made from this test-set ablation, because the validation
  split (the first 12 training dialogues) ranks the variants differently: it prefers the original IS10 audio. The
  gain of the final model over the baseline (+2.4 wF1, 5 seeds) is far larger than the seed noise, but the choice
  between WavLM + CACG and WavLM alone (+0.3) is not.
- **MELD test looks.** Keshav's L2 experiments had already evaluated the MELD test set three times; this is a further
  look. `w` and `T` are chosen on validation only.
- **What runs at inference.** The MELD system includes a 32B LLM, used through cached scores for the dev and test
  utterances. A new utterance would need the LLM to be run, and WavLM needs the raw audio.
- **No cross-dataset tests.** L1 was not tested on MELD (no audio extracted) and L2's LLM was not tested on IEMOCAP
  (no scores).
- **Not merged here.** Keshav's class-balanced loss (`--task_loss cb`, branch `merge/l2-l3`) is not in this codebase.

## 5. Reproduce

Data: the release feature pickles plus Divyansh's `iemocap_wavlm.pkl` and `iemocap_aux_labels.pkl` go in
`Limitation-3/ECERC/data/iemocap/` (gitignored). Keshav's cached LLM scores are already in
`Limitation-2/results/run_kaggle_zeroshot_1/outputs_zeroshot/`.

```bash
cd Limitation-3/ECERC/ext
python prepare_data.py                 # once: float32 feature caches
python prepare_extras.py               # once: WavLM + VAD/votes aligned per dialogue (IEMOCAP)
bash run_grid.sh IEMOCAP "2007 1 2 3 4" baseline cacg_noloss wavlm wavlm_l1 wavlm_cacg wavlm_l1_cacg
bash run_grid.sh IEMOCAP "2007 1 2" is10_l1
bash run_grid.sh MELD "0 1 2" baseline_g1 cacg_utility_g1 baseline cacg_utility cacg_noloss
python final_report.py                 # tables, incl. LLM fusion + temperature scaling -> runs/RESULTS_merged.md
```

The final model in one command per seed:

```bash
python train.py --dataset IEMOCAP --audio wavlm --gate cacg --gate_loss none --seed 2007
python train.py --dataset MELD --gate cacg --gate_loss utility --aux_heads --lambda_gate 1 --lambda_aux 0.5 --seed 0
```

Runtime on a GeForce 940MX (2 GB): about 5 min per IEMOCAP run and 4 min per MELD run. Run one job at a time on 8 GB
of RAM, because two in parallel swap and become 10× slower.

## 6. Demo UI

```bash
cd Limitation-3/ECERC
python ui/app.py            # runs the final models on both test sets (a few minutes on CPU), then open http://localhost:8000
```

The UI needs no extra packages (standard library server). It replays the test conversations: pick IEMOCAP or MELD
and a dialogue, and every utterance shows the predicted emotion, its calibrated confidence, ✓/✗ against the gold
label, and a ⚠ "unsure" flag on the 20% least confident predictions (the threshold is set on validation; flagged
predictions are right only 47% (IEMOCAP) / 38% (MELD) of the time, against 79% / 76% for the rest). Click an
utterance to see:

- all class probabilities, and on MELD the ECERC, LLM and fused probabilities side by side (L2);
- the CACG weights over the four cause types, with unavailable causes hatched, and the gate temperature τ (L3).

Links such as `http://localhost:8000/#MELD/1153/2` open a given dialogue and turn.

## 7. Code map (what was added for the merge)

| File | Change |
|---|---|
| `ext/prepare_extras.py` | new: aligns WavLM features, VAD and annotator votes to each IEMOCAP dialogue |
| `ext/data.py` | `--audio wavlm` swaps the audio slot; batches also carry VAD, VAD mask and vote distributions |
| `ext/losses.py` | `--focal_gamma` (default = the release value per dataset); `soft_label_nll` and `vad_loss` (L1) |
| `ext/train.py` | flags `--audio --lambda_vad --soft_beta --focal_gamma`; VAD head kept outside ECERC so checkpoints stay compatible; saves validation outputs too |
| `ext/final_report.py` | new: ablation tables, seed ensembles, L2 LLM fusion with `w` and `T` chosen on validation |
| `ext/dump_outputs.py` | new: re-evaluates older checkpoints to save their validation outputs |
| `ext/run_grid.sh` | merged variants added |
| `ui/app.py`, `ui/index.html` | new: demo |

With all new flags at their defaults, the first 3 epochs of IEMOCAP seed 2007 and the first epoch of MELD seed 0
match the earlier release-loss logs exactly, and `test_equivalence.py` still reports zero difference from the official
model.
